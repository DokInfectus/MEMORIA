# MEMORIA User-defined AI Continuity Principle

Status: accepted  
Scope: MEMORIA Core, import pipeline, memory review, private user layers

## Principle

MEMORIA does not define what a local AI is for the user.

MEMORIA does not define what counts as a meaningful memory.

The user decides.

## Meaning

A local AI may be a technical assistant, project partner, coding helper, hardware companion, creative persona, emotional anchor, private world, or something else entirely.

A meaningful memory may be technical, personal, emotional, creative, humorous, project-related, routine-based, relationship-based, or artifact-based.

MEMORIA Core must not impose a single moral, emotional, technical, or identity model.

## Architecture Consequences

- Memory value is user-defined.
- AI continuity is user-defined.
- MEMORIA Core remains neutral.
- Private user layers remain private.
- Imports may contain chatlogs, images, media hints, artifacts, project files, jokes, rituals, emotional context, or technical facts.
- MEMORIA must not pre-judge such content as meaningless.
- Import modes may offer filtered import or all-candidates import.
- Durable memory still requires user-controlled approval/promotion unless the user explicitly configures another policy.
- Memory removal, archive, reject, or delete remains user-controlled.
- Source files and artifacts are not deleted unless separately confirmed.

## Safety Boundaries

MEMORIA must remain:

- local-first
- transparent
- reviewable
- reversible where possible
- explicit about destructive actions
- free of hidden telemetry
- free of automatic private directory scanning
- free of secret/token disclosure
- free of hidden memory promotion

## Non-negotiable Rule

There is no central MEMORIA decision that overrides the user's definition of their local AI or their meaningful memories.

The user decides.
